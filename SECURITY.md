# TULPAR Security & Privacy Model

## 1. Zero-Server Operation, Local Processing & External DNS Transparency
- **Zero TULPAR Infrastructure & Zero Telemetry**: TULPAR operates with **zero central servers, zero relays, zero telemetry endpoints, zero analytics SDKs, zero crash-reporting libraries, and zero user accounts**. Your traffic is never routed through a server operated by TULPAR developers.
- **Zero Disk Logging of Traffic / Queries (Non-Traffic Local Preferences Only)**: Connection histories, DNS query logs, SNI hostnames visited, and destination IP addresses are **never written to disk**. All ephemeral runtime state (in-memory DNS LRU cache, per-destination adaptive DPI strategy map using salted SipHash keys, SYN-ACK hop calibrator, PQ stream reassembly buffers) lives strictly in volatile RAM and is immediately dropped/cleared when protection stops. Only explicit user settings (selected encrypted DNS preset, QUIC bypass mode, optional manually added domain allowlist/blocklist/DPI-exclusion rules) are stored locally when configured by the user (`%ProgramData%\Tulpar\config.json`, `/etc/tulpar/config.conf`, Android `SharedPreferences`).
- **Transparency on External Public DNS Providers (DoH / DoT)**:
  - **Blocked domains** matched by the local on-device ad/tracker/malware blocklist (`yolac-blocklist`) or user-defined custom blocklist overlay are answered locally in RAM (`0.0.0.0` / `::`) and **are never sent outside the device**. Domains in the user's explicit allowlist override blocking locally.
  - **Unblocked domains** not already served from the in-memory LRU DNS cache are resolved over encrypted **DNS-over-HTTPS (DoH, port 443)** or **DNS-over-TLS (DoT, port 853)** directly from your device to either the built-in public DNS providers selected by `DnsProfile` (`AutoFastest`, `Cloudflare`, `Quad9Security`, `MullvadAdblock`, `AdGuard`) or an explicit encrypted **Custom DoH/DoT** endpoint configured by the user (literal IPv4/IPv6 bootstrap IP + TLS hostname; plaintext `http://` and loopback IPs are rejected):
    - **Cloudflare DNS**: `1.1.1.1:443` (`cloudflare-dns.com`), `1.0.0.1:853` (`1dot1dot1dot1.cloudflare-dns.com`), `2606:4700:4700::1111:443`
    - **Quad9 Security DNS**: `9.9.9.9:853` (`dns.quad9.net`), `149.112.112.112:443`
    - **Mullvad DNS / Adblock**: `194.242.2.2:853` (`dns.mullvad.net`), `194.242.2.3:443` (`adblock.dns.mullvad.net`)
    - **AdGuard DNS**: `94.140.14.14:443` (`dns.adguard-dns.com`)
    - **Google Public DNS** (backup/race in `AutoFastest`): `8.8.8.8:443` (`dns.google`)
  - **What External Resolvers Receive**: While encrypted DoH/DoT hides DNS queries from your local ISP and on-path passive observers, **the active external DNS provider necessarily receives your client IP address and the queried domain name** in order to resolve the query, subject to that provider's own privacy policy.
  - **Connectivity & Health Probes**: On startup, network changes, or manual diagnostics (`tulpar test` / `tulpar doctor <domain>`), TULPAR probes configured public DNS resolvers (`one.one.one.one` A query over DoH/DoT), checks IPv6 socket reachability (`[2606:4700:4700::1111]:443` and `[2001:4860:4860::8888]:443`), and in the explicit Domain Doctor tool sends direct and split TLS `ClientHello` probes solely to the single user-specified domain.
  - **Manual GitHub Release Check & SHA-256 Verification**: Only when the user explicitly triggers an update check in Settings does TULPAR connect over HTTPS to `api.github.com` (`/repos/<owner>/<repo>/releases/latest`) to compare version tags. Release asset checksum verification helpers compare artifacts strictly against official `SHA256SUMS.txt`. No background update checks are performed.

## 2. Memory Safety & Privilege Boundaries
- The shared network core (`core/crates/*`) is written in Rust (`#![forbid(unsafe_code)]` in `yolac-dpi`, `yolac-blocklist`, `yolac-dns`, `yolac-core`).
- `unsafe` is strictly isolated to OS FFI/socket/packet boundaries (`yolac-net` socket FD protection, `yolac-ffi` C-ABI/JNI boundary, `platforms/windows` Win32/WinDivert bindings, `platforms/linux` Netlink `NFQUEUE`/`IPPROTO_RAW` bindings) with explicit bounds checks and null-pointer guards.
- Pure-Rust TLS (`rustls` + `webpki-roots`) avoids C/C++ OpenSSL memory-corruption surfaces.
- **Linux Privilege Boundary (`platforms/linux`)**: Uses `root` (`euid == 0`) or non-root ambient/effective capabilities (`CAP_NET_ADMIN` + `CAP_NET_RAW`, checked via `/proc/self/status`) for Netlink `NFQUEUE` (with `--queue-bypass` fail-open semantics) and `IPPROTO_RAW` (`IP_HDRINCL`/`IPV6_HDRINCL`), isolating outbound traffic in a dedicated `table inet tulpar` / `tulpar_output` chain and tearing down firewall rules and captive local DNS listeners cleanly on `SIGINT`/`SIGTERM`.
- **Rogue DoT (`TCP/853`) Leak Guard**: Third-party plaintext DNS (`port 53`) and unauthorized external DoT (`port 853`) flows outside the active TULPAR encrypted bootstrap upstream IPs are blocked cleanly on Windows (`WinDivert`), Linux (`NFQUEUE`), and Android (`TUN`).

## 3. Leak Prevention & Binary Integrity
- **DNS Leak Prevention**: All IPv4 & IPv6 UDP/53 and TCP/53 traffic is captured and resolved locally through `yolac-dns` (local blocklist + persistent keep-alive encrypted DoH/DoT with hardcoded bootstrap IPs). Plaintext ISP fallback is disabled (fail-closed), except for bounded local-LAN captive portal recovery.
- **Balanced Fail-Closed IPv6 Protection**: `probe_ipv6_leak_mode` checks protected IPv6 reachability; if IPv6 is broken or unguarded, TULPAR automatically switches to `BlockUnprotectedIpv6` + `AAAA` suppression so host IPv6 cannot leak.
- **Windows DLL & Driver Integrity Protection**: Elevated `tulpar.exe` verifies exact SHA-256 digests (`WinDivert.dll` and `WinDivert64.sys`), rejects NTFS reparse-point / junction tampering, stages verified driver files under `%ProgramData%\Tulpar\driver\2.2.2`, holds read-shared (`FILE_SHARE_READ`) locks to prevent concurrent replacement, and loads `WinDivert.dll` with `LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR | LOAD_LIBRARY_SEARCH_SYSTEM32`.
- **Bounded Captive Portal Safety**: Temporary local-LAN portal allowance activates only on consecutive encrypted DNS failures alongside captive portal indicators, is strictly capped at 90 seconds, and automatically closes when encrypted DNS succeeds again.
- **Release Checksums**: Tag-triggered releases (`v*`) publish `SHA256SUMS.txt` alongside all artifacts on `https://github.com/AtaberkGit1/TULPAR/releases`.
- **DoS / OOM Caps**: `TunEngine` enforces bounded concurrent DNS semaphores, strict max packet size (`<= 65535`), bounded TCP flow caps, and LRU UDP NAT eviction.

## 4. Reporting Vulnerabilities
Because TULPAR is open-source and runs locally, any security issue can be audited directly in the repository. Please avoid publishing exploit details before a fix is merged.
